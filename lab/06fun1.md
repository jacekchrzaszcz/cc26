## Lab 6 - functions

Goal: extend the compiler to *Lfun*: top-level function definitions,
`return`, and direct calls.

Scope for this lab:

- top-level `def`, recursion and mutual recursion, direct calls only
- no first-class function values - a function name can only be called,
  not passed around or stored in a variable (that's next lab)
- no tail-call optimisation - `return f(x)` is an ordinary call followed
  by a jump to the conclusion, so deep recursion uses stack proportional
  to depth
- at most 6 parameters (packing the rest into a tuple needs tuples, which
  we don't have yet)

## Lfun --- what is new

Concrete syntax, on top of `Lwhile`:

```
def name(param, ...): stmt+
stmt ::= ... | return exp
exp  ::= ... | name(exp, ...)
prog ::= def* stmt*
```

Abstract syntax:

```
FunctionDef(name, args, body, ...)
Return(exp)
Call(Name(name), [exp, ...])
```

`FunctionDef.args` is an `ast.arguments` object, not a plain list. Get the
parameter names with `[a.arg for a in node.args.args]`, and reject default
arguments, `*args`, `**kwargs` and keyword-only parameters - none of that
is supported.

Add function definitions, `return` and calls to the interpreter.

### shrink: wrap the top level in main

After `shrink`, a module should contain only function definitions. Move
every top-level statement into a function called `main`:

```
Module([def1, def2, stmt1, stmt2])
```
⟹
```
Module([def1, def2, FunctionDef('main', [], [stmt1, stmt2, Return(0)])])
```

This way `main` needs no special-casing in later passes: it is just a
function that happens to be called `main`.

### Collect function names and arities

Before compiling, walk the module and record each function's arity:

```python
function_arity = {d.name: len(d.args) for d in module.body}
```

Use it for two checks:

- calling a function with the wrong number of arguments is an error
- using a function name as a value, other than in a call, is an error
  (we don't support that yet - see "out of scope" above)

### remove_complex_operands

Two additions:

- `f(a1, ..., an)` - the arguments must be atoms; the function name
  itself is not made atomic, it names a label, not a value
- `return e` - `e` may stay complex, e.g. `return x if p else y`, so its
  shape survives into `explicate_control`

### explicate_control

A program becomes a list of function definitions, each with its own
block dictionary.

New function `explicate_tail(e, basic_blocks)`, for an expression in tail
position (the operand of `return`):

- `if`/`Begin`: explicate as usual, but each branch's own tail goes
  through `explicate_tail` again
- anything else: produces `Return(e)`

We don't support tail calls, so `return f(x)` falls into the second case
and becomes `Return(Call(...))` - no special case needed for it.

`explicate_stmt` gets a `return` case that discards its continuation -
nothing runs after a return.

`explicate_pred` needs nothing new. `if f(x): ...` leaves a test that is
not an atom, and lab 4's fallback already binds such a test to a
temporary before testing it - which is the case that stops every new
language from having to touch this function. Worth a test, not worth
any code.

Compile each function separately: its own block dictionary, its own base
continuation `[Return(0)]` (falling off the end of a function returns 0),
its own `f_start` / `f_conclusion` labels.

### select_instructions

A call:

```
lhs = f(a1, ..., an)
```
⟹
```
    movq a1, %rdi
    movq a2, %rsi
    ...
    callq f
    movq %rax, lhs
```

using the first `n` of `%rdi %rsi %rdx %rcx %r8 %r9`.

A function definition loses its parameter list and gains moves at the top
of its start block:

```
f_start:
    movq %rdi, x1
    movq %rsi, x2
    ...
```

Emit these moves even though they look redundant. Liveness on them is
what makes `x1` interfere with `%rsi`, which is what stops the register
allocator from putting `x1` in `%rsi` and clobbering `x2`'s argument.

### Liveness, interference, register allocation: per function

Everything from the previous lab still applies, but run it separately for
each function. Reset the interference graph - and anything else you kept
on `self` across a compilation - before each function. Otherwise
variables from different functions end up interfering with each other for
no reason, and everything spills.

### prelude_and_conclusion

Build a prelude and conclusion per function, as before. Only `main` needs
`.globl`; the rest are local labels. Flatten all functions' block
dictionaries into one before printing.

## Final checks

Create at least ten test programs exercising new features
- a non-recursive function with a few parameters compiles and runs
- calling a function with the wrong number of arguments is rejected
- a recursive function (`fib`) and a pair of mutually recursive functions
  (`even`/`odd`) compile and agree with CPython
- a function whose parameter is still needed after a call inside its body
  gets a callee-saved register (if available), not a stack slot
- callee-saved registers are not clobbered
- stack is aligned
